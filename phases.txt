3.4 FIX MANDATE ISSUES
-------------------------

  After the dry run, you'll probably find issues. Common ones:

  PROBLEM: Agents don't tag each other properly
  FIX: Add explicit tagging instructions to mandates
       "When your work is complete, @mention the [next role] agent"

  PROBLEM: Ghost Auditor reads the Coder's test files
  FIX: Add to Ghost Auditor mandate:
       "You must ONLY read the design document and the source code.
        Do NOT read any files in the tests/ directory."

  PROBLEM: Gatekeeper accepts without waiting for Auditor
  FIX: Add to Gatekeeper mandate:
       "Do NOT make any decision until you have received reports
        from BOTH the implementation agent AND the adversarial agent."

  PROBLEM: Agents go off-script or ignore their mandate
  FIX: Make mandates shorter and more direct. LLMs follow
       shorter, clearer instructions better than long ones.

  PROBLEM: The feedback loop doesn't work (no re-submission)
  FIX: Add to Coder mandate:
       "If your work is rejected, read the rejection feedback,
        make the required fixes, and re-submit for review."

  Update your mandate files with any fixes, then commit:
    git add mandates/
    git commit -m "fix: refined mandates after dry run"
    git push

  Paste this into the BAND room (this is your ONLY human input):

  """
  Build a wallet and payments JSON API service.

  REQUIREMENTS:
  1. Wallets:
     - Create wallets with unique IDs and optional names
     - Get wallet details including current balance
     - List all wallets

  2. Transfers:
     - Transfer money between two wallets
     - Each transfer must have a unique idempotency key
     - Sending the same idempotency key must return the same result
       (no duplicate transfers on retry)
     - A transfer must be atomic: both the debit and credit happen
       together, or neither happens
     - A wallet's balance must never go below zero
     - Transfer amounts must be positive and use exact decimal
       arithmetic (never floating point)

  3. Double-Entry Bookkeeping:
     - Every transfer creates exactly 2 journal entries:
       one DEBIT (negative) on the source wallet,
       one CREDIT (positive) on the destination wallet
     - INVARIANT: The sum of ALL journal entries across ALL wallets
       must ALWAYS equal zero
     - Wallet balance = sum of all journal entries for that wallet

  4. State Management (for test harness):
     - POST /state/import — load a complete state snapshot
     - GET  /state/export — dump complete state
     - POST /state/reset  — reset to clean state

  5. Health:
     - GET /health — returns 200 with status info

  TECH STACK:
  - Python 3.11 with FastAPI
  - SQLite with SQLAlchemy (async)
  - Pydantic v2 for validation
  - All monetary amounts as decimal.Decimal, stored as TEXT
  - pytest + httpx for testing
  - Docker container (python:3.11-slim base, no outbound network)

  CODE LOCATION: stage-1/ directory

  CRITICAL INVARIANTS TO VERIFY:
  - sum(all journal entries) == 0  ALWAYS
  - wallet balance == sum(journal entries for that wallet)  ALWAYS
  - same idempotency key → same response  ALWAYS
  - balance never negative  ALWAYS
  - no partial transfers (both entries or neither)  ALWAYS
  """

5.2 DESIGN SYSTEM — BLACK + RED THEME
----------------------------------------

  Your theme: Primary Black (#0a0a0a) + Secondary Red (#dc2626)

  ╔════════════════════════════════════════════════════════════════╗
  ║  TIPS TO MAKE IT NOT LOOK "VIBECODED" (AI-GENERATED)         ║
  ║                                                               ║
  ║  The #1 giveaway of a vibecoded UI is that it looks like a   ║
  ║  generic Bootstrap/Tailwind template. Here's how to avoid it: ║
  ╠════════════════════════════════════════════════════════════════╣
  ║                                                               ║
  ║  1. TYPOGRAPHY IS KING                                        ║
  ║     - Use "Inter" or "Space Grotesk" from Google Fonts       ║
  ║     - DON'T use the default system font                      ║
  ║     - Use font-weight variation: 300 for body, 600 for heads ║
  ║     - Use letter-spacing: -0.02em on headings (tighter)      ║
  ║     - Use line-height: 1.6 on body text (more breathing room)║

5.5 FRONTEND → BACKEND CONNECTION
------------------------------------

  The frontend talks to the FastAPI backend via fetch():

    const API = 'http://localhost:8000';

    // Get all wallets
    const wallets = await fetch(`${API}/wallets`).then(r => r.json());

    // Create a wallet
    const newWallet = await fetch(`${API}/wallets`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ name: 'Alice' })
    }).then(r => r.json());

    // Make a transfer
    const transfer = await fetch(`${API}/transfers`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        source_wallet_id: 'xxx',
        destination_wallet_id: 'yyy',
        amount: '50.00',
        idempotency_key: crypto.randomUUID()
      })
    }).then(r => r.json());

  CORS: FastAPI needs to allow cross-origin requests.
  Add to stage-1/app/main.py (or stage-2/app/main.py):

    from fastapi.middleware.cors import CORSMiddleware
    app.add_middleware(
      CORSMiddleware,
      allow_origins=["*"],
      allow_methods=["*"],
      allow_headers=["*"],
    )
